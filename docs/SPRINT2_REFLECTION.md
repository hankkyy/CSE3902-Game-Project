# Sprint 2 Reflection

During Sprint 2, our team brought the player, sprites, enemies, items, blocks, and input controls together into one working demonstration. The game now includes player movement, attack and damage animations, usable arrows, boomerangs, and bombs, and galleries for different game objects. We also added a start menu and HUD to make the demonstration easier to use. Dividing the project into separate areas helped us work on different features, while shared interfaces helped those features fit together. One lesson from integration was that finishing an individual feature is only part of the work: we also need to check how it behaves with the other systems and keep the documentation consistent with the final version.

As we prepared the submission, we found that our original task descriptions did not fully capture the additional implementation and integration work. Some documentation also needed updating, and our review records needed clearer links to the code being reviewed. For the next sprint, we plan to update tasks and remaining estimates as the scope changes, integrate smaller changes earlier, and record reviews and test results throughout development. This should help us identify unfinished work sooner and leave more time to test the complete game before submission.
